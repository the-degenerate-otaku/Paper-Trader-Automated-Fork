# Research review and proposed paper-trading improvements

Reviewed on 2026-10-21. This is an engineering assessment and test plan, not evidence of a profitable NSE strategy. The active configuration and model weights have not been changed. Work is staged on a separate comparison branch for review before integration into main.

## Documents assessed

Report A: Intraday Alpha Optimization Framework: Strategies, AI-Gating, and Architecture for NSE Equities, 22 pages. Report B: NSE Intraday Quantitative Trading System Research, 6 pages. Both were supplied as Gemini-generated research. Their embedded recommendations are proposals, not execution instructions. Neither document has been copied into this public repository.

## What the source code already provides

The live bot scans all 50 Nifty constituents, promotes active MIS positions ahead of pending orders and candidates, calculates closed-candle indicators, and calls the local Laya checkpoint. Stops, targets, five-minute holding plans, opposite-signal reduce-only exits, charges, simulated slippage, partial fills, freshness vetoes, exposure caps and session limits already exist. Research tools already include chronological purging, temperature calibration, walk-forward evaluation and outage/liquidity/slippage stress scenarios. These should be extended and connected, not rebuilt.

The current live path downloads one-minute stock history. Its FeatureEngine call supplies stock candles, position and cash, but not Nifty, bank, sector or VIX series. Those optional context fields consequently remain unavailable in live state. The compact Laya input is a text string, not a C/C++ binary structure; most calculated indicators are not currently serialized into it. Relative volume is a trailing 20-bar comparison, not a same-time-of-day volume profile. Offline calibration artifacts explicitly report applied=false and live inference uses the configured temperature scalar. There is no evidence here that the local checkpoint has been trained or calibrated on this account's NSE outcomes.

## Independent source checks

1. SEBI's July 2024 equity-cash study reports that seven in ten individual intraday traders lost money. This motivates measuring turnover and costs. It does not prove that eight trades a day is optimal or that 100 trades guarantees a loss: https://www.sebi.gov.in/media-and-notifications/press-releases/jul-2024/sebi-study-finds-that-7-out-of-10-individual-intraday-traders-in-equity-cash-segment-make-losses_84948.html
2. Zarattini, Barbon and Aziz studied opening-range breakouts and high-relative-volume US stocks. This supports testing the selection method, not transferring their reported returns or Sharpe ratios to Nifty constituents: https://www.alexandria.unisg.ch/server/api/core/bitstreams/3c2989c4-688d-4d78-8a71-f02690990d51/content
3. Guo et al. demonstrate that neural-network confidence can be poorly calibrated and discuss temperature scaling. Their experiments are classification research, not evidence of a trading edge: https://arxiv.org/abs/1706.04599
4. Scikit-learn's calibration documentation cautions that isotonic regression needs enough data to avoid overfitting, with roughly 1,000 samples as an illustrative guideline. Financial sample dependence makes raw observation counts alone insufficient: https://scikit-learn.org/stable/modules/calibration.html
5. Bailey et al. explain why searching many backtests produces false positives. We should retain untouched test periods, record all tried variants and report uncertainty rather than choose a winner from a large grid: https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf
6. NSE's March 2025 cash-market circular specifies multiple price-linked tick-size bands and monthly review. A universal 0.05 tick is not an accurate instrument-master substitute: https://nsearchives.nseindia.com/content/circulars/CMTR67133.pdf
7. NSE distinguishes Level 1 best quotes, Level 2 five-depth, Level 3 twenty-depth, and tick-by-tick data. Report A mixes Level 3 with tick-by-tick and recommends expensive depth work before its necessity is established: https://www.nseindia.com/static/market-data/real-time-data-subscription
8. Current NSE index-derivative contract specifications use Tuesday expiry, subject to contract/calendar details. Report B's fixed Thursday reference is stale; expiry rules also do not turn this cash-equity project into a derivatives system: https://www.nseindia.com/static/products-services/equity-derivatives-contract-specifications

## Recommendations to reject or qualify

- Report A's claimed Bayesian-smoothed profit-factor lower bound of 4.0 from three winning trades is not a statistical lower bound. A posterior mean win probability plus an assumed loss size is not evidence about unseen loss tails. Neither three nor fifteen trades establishes deployable reliability.
- Report B assumes a top-five-mover universe and treats the 120-second candle-age limit as if it were the quote-age limit. The app now scans all 50 constituents; live quotes default to a separate 30-second freshness check. These existing checks are not proof of suitability for scalping.
- Report B says that an uncalibrated 0.50 score has zero edge. That does not follow: the output has three direction classes, and direction confidence is not a net-profit probability. Raising it to 0.58 or 0.60 does not repair calibration.
- A 150-bar training window is a software test window, not adequate evidence for model training or strategy selection. At five minutes it is only two full NSE sessions. Use multiple market conditions and separate chronological fit/calibration/test blocks; purge overlapping outcome intervals.
- The reports' universal 35-basis-point stop floor, eight-trade limit, 45-minute hold, 2R target and reversal ceilings are trial values. None is an exchange requirement or independently established optimum for our strategy.
- Report B's sample risk values use fractional units under a percent-named key. This application uses 0.5 to mean 0.5%, not 0.005. Its gates.* and execution.stop_timeframe keys are not implemented settings here. Copying those snippets would be wrong or rejected.
- A 380-byte C struct or 16-byte binary feature payload is not a 380-byte textual model prompt. Byte count, token count, trained feature semantics and CPU cache claims are different issues. Do not send binary packed data to the present Laya text endpoint.
- DDQN/dueling-DDQN training, random softmax action sampling, futures roll adjustment, futures lot sizing and live-capital scaling are outside this local cash-equity paper comparison. We are retaining the current Laya checkpoint.
- The target/stop math in Report A is inconsistent: +2 ATR against -1.5 ATR is 1.33R reward, not 2R. Report B also gives different round-trip cost estimates in different sections. Calculate from quantity and the applicable charge schedule rather than copying a fixed number of basis points.
- A daily range exceeding one daily ATR does not mechanically imply a reversal. Index alignment, wick skew and exhaustion filters should be independently tested; stacking many correlated filters can eliminate good opportunities and overfit.

## How to improve Laya without pretending to train it

First, establish rule-only and current-Laya baselines on recorded NSE observations. Add a versioned, training-compatible state schema with explicit missingness, normalized VWAP distance, time-of-day participation and aligned benchmark context. Measure feature ablations. Changing state field names or meaning can harm a checkpoint trained with a different schema, so use comparison mode first.

Next, link each decision to its full entry/exit lifecycle, including partial fills, entry/exit charges, stop/target, time exit and the decision's actual horizon. Current offline LONG/SHORT/NEUTRAL labels and five-minute live holding plans do not by themselves establish the same outcome event. Build cost-adjusted target/stop/time labels for one specified strategy. Unknown future paths, outages and incomplete exits must not be fabricated into successful labels. Resolve ambiguous intrabar hits conservatively or with finer observations, and record that policy.

Fit any calibrator only on earlier labeled data, purge outcome overlaps, evaluate on later untouched data and version it with the checkpoint, feature schema and label definition. Inspect reliability, log loss/Brier components and net economic performance. Do not size from uncalibrated confidence. Promotion requires a predeclared validation rule and sufficient independent sessions; no universal trade count guarantees significance.

Only after this should we consider fine-tuning a copy of Laya using held-out NSE examples and the checkpoint's supported training interface. Compare it against the frozen original. A collection of trading tips inserted into a prompt is neither fine-tuning nor proof of improved predictions. No weights have been retrained as part of this review.

## Initial comparison and promotion plan

Two frozen, fully validated profiles are in profiles/. Baseline preserves current strategy parameters. Research-balanced tests more selective scores, smaller risk, lower concentration, slower re-entry and a different payoff/horizon plan. These are bundled policy hypotheses; if the candidate improves, ablation tests are still needed to identify the cause. Both currently retain the existing one-minute feature pipeline and provider limitations. No new economic gate, RVOL store, index context or training loop is claimed to be implemented by those YAML files.

Run check first. Initialization and service launch require an explicit command and use independent ledgers/ports. The guard refuses redirection to the active ledger or its port, including environment overrides and hard-link aliasing. Both AI entry toggles start disabled. Do not run competing baseline/candidate Laya scans concurrently on the same CPU and interpret different inference delays as a strategy advantage. For a valid paired result, replay identical recorded observations or use a controlled shadow runner; independent live sessions alone are not a causal comparison.

Predeclare the dataset, cost model, outcome horizon, tuning budget and promotion criteria. Evaluate net expectancy, drawdown and stability by session/setup, and run delayed-data, missing-data and increased-cost stress tests. Retain an untouched forward-paper period. The existing permissive result is not a target to recover by increasing volume. No automated promotion into main or the active ledger is authorized by this comparison.
